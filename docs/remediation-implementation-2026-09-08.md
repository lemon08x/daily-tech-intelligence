## 已实施

1. **事件与证据归属**：GitHub issues、discussions、pull 不再继承承载仓库的项目标识；同仓库的不同投稿、不同版本发布不能仅凭相似标题合并。明确指向项目的投稿仍可与项目发布关联。Scout 输入补齐 document_id 和 URL。泛读事实必须同时绑定复排实际输入中的连续引文及当前事件文档；删除“任取前三篇原文”证据回退。每条受支持断言的审核引文也必须是连续原文，拼接引文不能放行；缺少旧式证据索引时，可直接使用审核通过的断言原文作为证据，主链接优先绑定已核验标题的来源。
2. **数值比较**：删除全文任意数字最大值比较。表格按指标、主体及测试条件比较；限定某个数据集时只比较该范围。百分数与比例归一化，单位或范围不明确时拒绝排序。模型补充比较行必须能在指定文档的连续引文中确认主体、指标、数值、单位和条件。有限范围的金额陈述由来源中的相同对象、时间条件和金额约束，不会读取 URL 数字。缺乏范围的最高/领先结论仍然降级。
3. **固定断言协议**：先规范化草稿，再生成一次断言清单，交给 Verifier 与确定性质量门共用。中文句号、问号、叹号不再依赖后续空格；小数、常见英文缩写及 URL 不被切开。Verifier 可省略重复的文本及字段位置，由固定编号绑定原清单；若返回文本和位置，仍严格匹配。分别诊断重复、未知、缺失和文本变化。审核缺失不再被展示为已证伪的事实。
4. **解析与重试**：OpenAI SDK 的自动重试设为 0，客户端只请求一次，ModelStageRunner 统一最多尝试两次。跳过说明中的数组及不符合 schema 的完整对象，不从破损对象内部截取子对象冒充答案。空响应、截断、语法和 schema 错误分别记录；每次尝试留存 finish_reason、耗时及已知 tokens，未知用量明确标记。删除重复注入的 schema。
5. **审计留存**：调用前保存实际阶段输入；每次请求保存结果或错误类别；Analyst 草稿在 Verifier 之前落库，Verifier 失败仍保留先前记录。保存质量决策、最终发布对象及缓存复用记录。最终发布记录包含选题次序和展示层级。旧缓存必须匹配策略、schema、内容快照并能取回该快照，才可复用。
6. **状态与日期展示**：失败研究不进入精读摘要；质量降级与材料不足属于独立维度，7 条降级加 3 条失败不会因其中 1 条材料不足而漏计。首次刊登查询实际 publication_ledger，来源日期不再冒充首次刊登时间。页面以中文展示主要原因，未知用量不标成精确统计。

提示词升级到 `tech-intel-v7`，质量策略到 `evidence-gate-v4`，断言 schema 到 `claim-audit-v2`；缓存身份另包含 `event-identity-v2` 和 `fixed-claims-v2`。现有 SQLite 表按追加方式使用，不删除或重写历史分析。
