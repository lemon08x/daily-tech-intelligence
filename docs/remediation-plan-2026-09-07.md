## 4. T1：按结论审查，并核对数值、范围与来源冲突

主要改动：`core/models.py`、`intelligence/prompts.py`、`modeling.py`、`quality.py`、`research.py`。

### 4.1 结论与证据契约

1. 为草稿中的标题、独立速读句、摘要、关键事实及其他实质性断言建立可追踪的 claim 标识；至少记录字段路径、原始文本、审核状态及来源位置。模型生成的 claim 清单不能代替程序核对字段覆盖情况。
2. 扩展 `VerificationResult` 为逐项结果，状态至少包含 supported、unsupported、conflicting、unverifiable。继续兼容读取旧 `unsupported_claims`，但旧结果不能自动满足新发布要求。
3. 一个字段含多个断言时需要全部被覆盖；不能拿该字段中的一个真实数字证明整段结论。审核结果缺失、id 重复、字段路径失效或审核文本与草稿不一致，都视为关键内容未核验。
4. 证据记录 document id、输入快照 hash、原文位置和精确引文。位置可以是字符偏移加表/章节定位；必须回查实际送入该阶段、已裁剪的文档。不能在模型未见的完整原文里补找证据。
5. Verifier 需要独立检查相关表格、反例与限制段落，不只审核 Analyst 挑出的引文；同时审核解释性文字是否偷偷引入新的效果、排名或因果结论。
6. 已验证事实与条件性研究判断分开记录。6–24 个月展望可以基于材料提出明确标注的不确定判断，但不能把预测写成已验证结果，或把来源未提供的数字、产品能力当作预测前提。无需为了保留展望而降低事实核验要求。

### 4.2 数值和范围检查

对“领先、最高、首次、提升、降低”等结论，要求给出相应核验材料：

- 数值比较：对象、指标、指标方向、数值、单位、基线、测试集/任务和实验条件。
- 百分比：相对变化与百分点变化分开，例如 54.0% 到 64.2% 是 +10.2 个百分点，约 +18.9% 相对提升。
- 最高/领先：列出该比较范围内的相关对比行；无法确认范围完整时，禁止整体领先结论。不同任务、不同测试条件的数值不能直接排序。
- 首次：仅有作者“提出一种方法”的描述不足以证明首次；来源支持缺失时删除该断言。

程序对可可靠解析的数值与原文片段做一致性和算术检查，拒绝“枚举为 pass 但数值关系不成立”的结果。解析器采用明确、可测试的表格/文本格式边界；无法恢复表头、单位或比较条件时降级，不能猜测，也不能声称已实现任意 PDF 的通用事实验证。

SENTINEL-RL 的处理应指出作者叙述与表格矛盾，并拒绝“F1 领先”；也不能顺势声称在严格同条件复现实验中 LMDetect 全面更优，因为表中基线可能来自各原作者报告。

### 4.3 质量门约束

- 关键结论存在 unsupported、conflicting、unverifiable 或未审核状态时，即使模型 verdict=pass 也不得 deep。
- 保留现有精确引文、一手来源、事实/风险数量和长度要求。删除内容后重新检查最低要求；内容不足应降级。
- 不用字符串关键词清单单独决定所有结论真伪；关键词只能触发额外核验。
- 归一化、截断或编辑不得改变已审查结论的含义；发生实质性改写必须重新审核，不能沿用原审核标识。

## 5. T2：降级时清理不支持内容，显示真实流程状态

主要改动：`quality.py`、`research.py`、`reading.py`、`pipeline.py`、`publication/plain_digest.py`、`reporting.py`、`templates/report.html.j2`。

### 5.1 安全发布内容

- 对已判错的字段，默认删除整个字段/条目；仅保留有独立审核记录的完整断言。不要用正则删除“最高”后就认定改写已被审核。
- 不支持的 headline 不得继续作为正常标题。可用已审查通过的候选标题；若无合格标题，使用中性“待核验：来源材料”入口，原始来源题名放入明确标为原文的材料区。
- 若没有可核验摘要，则展示真实来源摘录和待核验提示。Scout 的未深研摘要不能自动成为深研降级后的“已核验摘要”。
- 不支持的分析和影响推断可以保存在 SQLite 草稿审计中，不得继续出现在正常标题、速读、正文要点或预览内容中。
- 纠错提示可以点明争议内容，但必须清楚标为“未采信”，与正常结论区分；避免靠隐藏的 details 承担唯一提示作用。
- 通过质量门但未达到精读材料门、深研失败、仅泛读是不同情况，不能将它们合并为“未进入前十”。

### 5.2 流程状态与阅读页签分离

在运行结果中传递结构化状态，字段命名可按现有契约调整，但必须能表达：

- 最终 selection order、是否是本次前十研究目标。
- 当前研究结果来自新调用还是已核验缓存。
- 仅泛读、研究失败、质量降级、质量通过，以及材料门是否通过及原因。
- 实际 publication tier（精读/泛读）、原始质量 issues 和可读的公开提示。

页面不根据 publication tier 反推研究历史。材料合格但质量降级的条目可以保留在精读页的“已深研线索”形式，必须仅展示安全内容并在标题附近说明降级；不强制填满十条深度结论。

PAIR 和 GPT-6 的回归样例应分别保存 selection order 4、7，页面标注“已深研，材料不足，转为泛读”，并显示各自质量问题；不能再显示“未进入前十”。

### 8.1 保存真正可复核的阶段材料

- SQLite 追加保存每个研究事件的实际阶段输入文档快照、结构化草稿、结构化 Verifier 结果、最终质量决定与公开结果。记录 run id、event id、阶段、实际模型、实验、缓存作用域、提示词/策略/schema 版本、时间和用量估算标志。
- 快照保存实际送入阶段的裁剪文本及 hash，必要时用内容寻址去重；不只保存可被后续覆盖的 documents 行 id。缓存命中记录引用哪个既有审计版本。
- 仅泛读保存该次运行的选题/公开材料出处；不能写入 `analysis_variants` 冒充研究分析。发布 ledger 与研究缓存是不同职责。
- 只记录必要的结构化结果，不保存模型隐藏推理、HTTP 授权头、API 密钥或 `.env` 内容。
- 数据库迁移只增量修改，保留旧分析、旧运行和历史输出；旧记录缺少新字段时允许只读展示历史状态，不补造逐项核验结果。

### 8.2 缓存契约

- 升级 `llm.prompt_version`、质量策略版本以及 broad-reading/选题缓存版本，保证结构和行为变更对应新的缓存作用域。所有默认值、生产配置和相关测试保持一致。
- `prepare_cached()` 除精确引文外，还要检查新审核覆盖、质量策略/schema 版本和所用材料指纹；材料发生实质变化时不得沿用旧的 deep 审核结果。
- 仅空白归一化可按照现有规则恢复为原文精确片段；实质内容变化或没有可追溯审计的旧结果需要重新研究，或在无法研究时明确降为未核验线索。
- 缓存失效是创建新版本，不是删除或覆盖历史审计。第一轮新版本运行可能出现更多缓存 miss，必须如实解释其成本，不能以复用旧结果掩盖。

### 8.3 质量摘要

分别统计：前十研究目标数、新调用数、缓存命中数、深度通过数、质量降级数、研究失败数、仅泛读数、材料门转入泛读数。区分终态分组与可重叠的原因计数，避免重复计数。

示例：基线应表达为“研究目标 10；通过 6、质量降级 4；仅泛读 30；页面精读 8、泛读 32”，而不是“34 条分析失败”。

- 将对外“质量分 100/100”改为明确的规则检查结果与证据范围；内部 score 可保留用于诊断。
- 分开统计研究样本均分与泛读数；不突出混合均分。
- 主视图优先展示规则状态、证据数、一手来源数和日期。若展示模型 confidence，明确是模型自评，不表述为事实准确率。
- 新增最近 24/48 小时比例、与上一份生产日报的事件重合率、新增材料数、来源分布、失败来源数，均注明统计口径和分母。
- 阮一峰投稿池失败继续公开为采集缺口；已有凭据可通过环境使用。不要为解决匿名配额把 token 写入配置或承诺一定能恢复。新增来源和配额治理不作为本次质量整改的阻塞项。
